# 持久化provider适配器（假服务验证）

2026-09-09，`canary-provider-adapter.ts` 把固定HTTP请求格式、响应白名单和逐调用日志接通；transport由调用方显式注入，不默认调用全局fetch。真实远端凭证桥接和执行入口尚未接入，不代表真实canary完成。

## 行为

- `frozenEmbeddingRequests()` 按已冻结v2计划生成14次文档嵌入和8次查询嵌入。文档组和查询组独立计数，源文档/题集不修改。
- 请求仅接受既定非Pro BGE-M3/重排模型、严格字段和数量，单输入最多4096 UTF-8字节；query embedding一次仅1文本，文档批次最多4文本，rerank最多20候选且全部返回。附加凭证字段、其他模型和不合法参数在首次调用前拒绝。
- 固定HTTPS端点、禁止重定向、20秒单请求超时、256KiB响应上限，不重试。只有回调通过响应校验、脱敏并完成持久化后，日志执行层才进入下一请求。
- embedding只保留合法唯一index、1024维float32有限非零向量及已知用量；转换后全零、溢出、维度/模型不符均失败。rerank只保留唯一有效index、有限降序分数和已知用量，丢弃document等回显。未知用量保存null，不记0。
- HTTP或校验失败后日志维持未知状态，禁止重调或继续后项。成功批次可不提供Key直接读取已保存结果；新批次缺Key在预约前拒绝。日志不保存Key、请求正文或服务端额外字段。

## 已验证和限制

假服务实跑冻结22次嵌入，以及独立8次重排批次；二次读取不提供Key、没有新增transport调用。测试覆盖故障停止、输入/响应上限、模型错配、float32下溢/溢出、零向量、重复/无效/无序排序、用量未知、敏感回显剥离与取消。

首轮类型检查发现数组长度14→22的收窄问题，改为显式文档14/查询8两个数组后通过；未绕过类型校验。旧`grounded-canary-provider.ts --execute-approved`入口已显式拒绝，防止仅修改executionId就复用两次失败的stdout执行链；旧预检和审计保留，旧批次标记不动。

下一步打包远端执行入口，接入只读凭证桥接和已验证的受限分块存储，先用假provider完成端到端演练。当前没有新增远端/真实模型/数据库调用、没有修改生产配置或部署；新真实批次仍须独立授权。
