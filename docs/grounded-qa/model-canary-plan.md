# 模型能力小样本与发布前验证

用户选择：完整可信问答MVP验收后部署，不单独发布幂等热修。现有UI保持，已有原生PG合成验收不替代真实模型和人工评测。

## 下一授权门：只读配置核验与极小合成探针

待单独授权后执行：先只读核对现有Petrichor的用途绑定、模型/版本/维度、provider协议及base URL；不返回、导出或复制API Key，不修改模型绑定。已有embedding/rerank为空、维度不兼容、端点身份不清时停止，由用户选择模型。

建议探针只含虚构测试文本，不含群聊、GeneOps或账号数据：一次embedding请求，4段文本、总计不超过2000字符；一次rerank请求，1个查询和4个合成候选。无自动重试，不创建索引Job、不启动Worker、不写生产数据。验证向量数量、维度、有限非零值，rerank返回候选身份/数量/分数及顺序；记录安全聚合、耗时和实际usage，未知费用不伪装为0。嵌入/重排费用或额度规则在调用前确认；CPA聊天/Deep无美元上限的决定不扩展为这些服务的无限批处理。

能力检查通过仅证明接口可用；没有人工标签及代表性评测不能宣称模型效果达标。

## 后续阶段（不在上述两次探针内）

1. 核对固定60题及证据身份，建立人工支持度审阅表；真实文档留受限环境，不进Git。
2. 独立批准有限文档索引canary及模型用量；检查原文/分片hash、版本、索引切换、检索Recall@20、语义改善和术语不退化。
3. 在Staging验证真实上传→索引状态→范围提问→定位引用→手动Deep→取消/刷新恢复；人工引用支持precision≥95%，相关题Recall@20≥0.85，测量检索P95/8秒预算和Deep180秒deadline。
4. 生产发布前重新核对实际运行SHA/镜像/备份/待迁移/flags，独立审批生产迁移与Worker启用，保留旧镜像和旧generation；失败不切换。

不得将两个接口探针扩成全量向量化、真实资料外发、GeneOps抓取/治理或生产模型测试。阶段结束更新DEV_STATE并提交安全代码/聚合报告，不提交凭据或受限部署元数据。
