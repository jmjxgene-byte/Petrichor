# 统一资料源超时修复

2026-09-10 正式站首次资料问答的可见 Run 显示 `source.lookup` 在 8 秒工具预算内失败；只读步骤元数据确认失败类别为 `TOOL_TIMEOUT`，没有读取或保存问题、正文、查询参数或模型响应。根因是统一检索把本地、GeneOps 等适配器放在同一个 `Promise.allSettled` 中，但慢速外部搜索仍能占满整个工具预算，导致已完成的本地结果也来不及进入深读。

修复后的 `sources.ts` 为每个适配器创建独立 AbortSignal 和有界 Promise，搜索阶段最多使用 4.5 秒并为深读保留 3 秒，深读阶段并行且单候选最多 3 秒；混合范围的慢速或失败外部源只进入固定 `source_timeout`/`source_unavailable` 降级码，本地候选仍可完成搜索和证据读取。仅外部源时仍 fail-closed，不回退到本地或旧快照；已知文档版本冲突保留明确安全提示。底层适配器收到子信号，避免留下未受控请求。

新增回归覆盖混合范围外部搜索超时、外部深读超时、本地证据保留和错误文案脱敏。定向测试 14/14 通过；完整测试 1,654 通过、40 个既有跳过，typecheck、lint、build、audit 通过。修复尚未部署到生产，下一步使用新镜像完成 staging/正式站同一安全查询验收，并观察降级计数与延迟。
