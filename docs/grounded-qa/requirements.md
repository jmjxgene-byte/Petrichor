## 功能需求

| ID | 需求 | 可验收行为 |
|---|---|---|
| G01 | 资料优先 | 内容问题必须先检索；零证据不得静默生成业务结论 |
| G02 | 豁免边界 | 问候、明确翻译、纯排版可直接处理，不新增业务事实；“怎么翻”不是明确翻译 |
| G03 | 澄清与补检 | 原问题保留，最多一轮补检；不足或关键语义冲突时询问，不擅自选解释 |
| G04 | 范围一致 | 搜索、阅读、引用、Deep 均在本轮冻结范围内；权限变化实时复核 |
| G05 | 锚点深读 | 文档中后部命中进入证据，邻近扩展不能挤掉核心命中 |
| G06 | 证据与来源 | 同文档多个片段不丢失；分别显示文档/片段计数；刷新后可恢复位置 |
| G07 | 状态诚实 | 上传、词法、语义状态分离；不伪造准确率、来源、时间或处理进度 |
| G08 | 增强检索 | 中文词法+匹配空间的向量召回、RRF、重排；真实降级可见 |
| G09 | 索引版本 | 原文件/文档 ID 保留；新 generation 完整验收才切换，旧索引可回退 |
| G10 | 手动 Deep | 同范围、多查询、可取消/恢复；最终只追加一次，保留快速回答 |
| G11 | 外部边界 | 不绕过 GeneOps contract/quality/restricted 门，不复制原始正文，不开启未就绪能力 |
| G12 | 通用知识 | 只有用户明确要求才另行补充，和资料结论分开，不自动联网 |

## 非目标

不替换 Petrichor、不部署第二套 WeKnora、不迁移账户；不改变 GeneOps 抓取、时间线或 FNS；不全量生成 Wiki/Graph；不逐条大模型清洗群聊；不公开私有文件；不以删除数据回滚。

## 模型与资源边界

优先复用已有配置，但聊天兼容接口不代表支持 embedding/rerank。批处理先提交目标服务、样本/分片/token 数、价格依据、总费用上限与停止条件，独立授权后才运行。服务能力或费用不可核实即停。默认 Auto Start、GeneOps Hybrid/Wiki/Graph 不变。索引/Deep 各一个活跃任务，并控制共享进程资源。

## 固定评测规格

60题固定分组：术语/口语15，长文靠后命中15，跨片段综合10，追问/歧义10，无答案5，时间/冲突5。实施时建立版本化题目与期望证据身份，先测旧实现再测新实现；没有人工标注及真实运行，不报告已达标。公开仓库只提交合成语料/题目；私有文档测例保留受限环境，提交安全聚合报告。

- 内容题100%有检索或明确失败记录。
- Recall@20≥0.85；定义为前20候选覆盖人工标注相关证据的比例，只在有答案题计算。语义子集改善，术语题不退化。
- 引用支持 precision≥95%，按人工审查的事实性结论—引用关系计算；不把有效引用ID或模型自评分当支持证明。
- 长文末尾、同文档多个位置、引用刷新、来源删除/权限撤销均有回归。
- 越权和 restricted/removed 泄漏为0；未知时间不能断言最新。
- 幂等、取消、租约恢复、崩溃、exactly-once和累计预算全部覆盖。
- 本地检索P95目标≤3秒，快速检索阶段硬预算8秒，Deep总deadline180秒。记录冷/热态、并发、provider耗时；这些是待测目标，不是现状。
- 冻结安装、bun test、bun typecheck、bun lint、bun build、bun audit --audit-level=high通过。失败区分改动、既有和环境原因，不弱化检查。

## 发布门与台账

基线→文档/视觉确认→统一检索与锚点→索引/Hybrid/Deep→离线迁移与合成测试→独立授权小样本→Staging→独立授权生产。每阶段更新根 DEV_STATE.md、审查 diff、范围明确提交推送，不合入主分支、不自动发布。线上回滚目标须当场核验；先关新增语义/Deep并切旧 generation，必要时回旧镜像。所有原文、旧索引、历史对话与回滚镜像保留。
