# 可信资料问答：用户路线与视觉确认

日期：2026-09-08。状态：设计交付，等待视觉确认；不是功能上线声明。

## 用户目标

继续使用 Petrichor 现有助手，选定资料后得到可追溯的回答，不需要学习提示词、不重新上传文件，也不需要了解 embedding。主要场景是中文群聊资料、知识库及只读 GeneOps 问答。用户已选择保留 Petrichor、现有界面微调、一次交付增强检索、有限补检后澄清、复用现有模型服务和手动 Deep。

## 主路径

| 阶段 | 用户动作与可见状态 | 系统行为 | 异常出口 |
|---|---|---|---|
| 准备资料 | 上传后看到关键词就绪、语义处理中或增强就绪 | 上传与索引状态分开，原文件身份不变 | 明确失败，不要求重复上传 |
| 选择范围 | 全部、仅本地或指定来源 | 本轮冻结范围；阅读时仍重新校验权限 | 来源失效要求换范围，不能暗中跨库 |
| 提问 | 自然输入短句或追问 | 内容型问题先检索，不让模型自行决定是否查资料 | 问候、明确翻译、纯排版可豁免 |
| 快速回答 | 检索资料→阅读片段→生成回答 | 有证据才能输出业务结论 | 一轮有限补检后说明不足或澄清 |
| 澄清 | 用自然语言或快捷选项回答 | 保留问题与已确认语义，不需新建对话 | 不能把含糊的“怎么翻”自动当翻译 |
| 查证 | 点击引用，展开原有依据抽屉 | 高亮命中片段，展示邻近内容和已知时间 | 无锚点的旧来源只允许打开原文 |
| 深入 | 点击深入检索，可取消或离开 | 后台多查询、多来源核对，追加补充 | 失败不覆盖原回答，不自动重启付费请求 |
| 追问 | 沿用语境或切换范围 | 每轮检查范围和引用；旧答案不是新事实证据 | 权限撤销后不重放敏感原文 |

## 四状态原型规格

使用浅色背景、现有侧栏层级、现有顶部面包屑与底部输入框；不新增工作台。生图可能改变图标、侧栏缩进、布局比例，实施时一律沿用已有组件，不将这些变化视为需求。移动端沿用现有抽屉/弹层，不另设桌面侧栏。

1. **有依据回答**：窄状态条、正文引用、文档/片段分别计数，次级动作“深入检索”。状态源于真实执行事件，不是定时动画。
2. **需要澄清**：问题“翻新怎么翻？”，询问 Listing 翻新、实物翻新还是英文表达；选项只是帮助输入，支持用户自行说明。不得自动选中并发送。
3. **回答依据**：沿用来源抽屉，文档下保留多个片段；高亮核心命中，前后文折叠。未知时间显示“时间未知”，不得用绿色暗示新鲜度或可靠性。
4. **深度任务**：保留原快速回答，展示排队/执行/完成/取消/失败和取消动作。完成后追加，不在进行中伪造完成答案。

所有原型标记“设计原型·虚构数据”；示例群名、消息、统计仅用于设计，不来自用户资料。图片不包含实际邮箱、账号或生产地址。中文文案以本文件及[需求文档](requirements.md)为准。生成提示词与最终图片放在 prototypes/，供后续视觉审阅；生图不是交互或性能验收。

## 用户确认门

确认四状态的信息层级、澄清交互和原文定位方式后，才实现 UI 与核心功能。任何模型批处理、生产迁移、Worker 启动和部署仍需后续独立批准。当前设计不要求重导入原有 21 篇文件。
