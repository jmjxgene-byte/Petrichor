# 手动 Deep 用户入口

本阶段仅功能分支实现，未部署、未启动真实Worker或调用模型。

- 现有助手回答下增加“深入检索”，要求完成/停止状态且有服务器问题ID；Wiki模式不提供此入口，Deep补充自身不能递归启动。
- 列表接口`POST /api/assistant/deep-research/list`验证登录、会话归属与未删除状态，按user/thread读取最多100条最新任务，仅返回已有安全任务响应、开关状态及保存范围/hash。
- 页面按fastRunKey恢复任务状态；仅用户点击start/cancel才写入。未知操作结果不自动重发，通过手动刷新恢复；有活跃任务时每3秒查询状态，读取错误后暂停自动轮询。
- 显示服务器保存范围；start携带expectedSourceScopeHash，保存范围改变则后端拒绝，不使用输入框尚未发送的新选择。旧API调用仍兼容可选字段。
- 完成后只读取同一用户的会话消息并匹配resultMessageId/agentRunId，通过已有assistant-ui的append加`startRun:false`追加助手消息，不覆盖快速回答或发起新模型调用。进行中的普通回答结束后才追加；按Run去重，异步返回不能更新已离开的会话。
- 保持原侧栏、正文、输入框、按钮与消息渲染组件。历史来源复用已有Deep元数据恢复机制，没有新增原始外部chunk副本。

## 验证

1479项全量测试通过、40既有跳过；typecheck/lint/build/diff通过。新增测试覆盖用户/会话隔离、范围变化拒绝、不开启时禁用、手动启动取消、写入超时不自动重发、会话切换/StrictMode、结果追加不启动模型。

浏览器使用`/demo`下“深度检索交互演示（虚构）”验收：启动/取消、完成后原回答保留且追加一次、切换会话再回来恢复、最终保存范围提示均可见，控制台未见错误。演示在浏览器内存中模拟，刷新会重置，不调用服务或模型。预览进程与标签已关闭。

未验证：真实PostgreSQL与Worker端到端、生产权限/日志、上游额度错误分类、真实资料检索支持度、移动视口、极长会话超过100任务的完整发现。列表limit是保护上限，不声称无限历史覆盖；完整MVP仍须后续验收。
