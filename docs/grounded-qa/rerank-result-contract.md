# 重排结果消费契约

2026-09-10：新增离线重排结果消费模块。输入只允许 `results[{index,relevance_score}]` 和 `usage.total_tokens`，响应必须与候选数量一致，索引按0开始连续且分数非递增；越界、重复、缺索引、乱序、额外字段或正文回显均拒绝。候选ID必须唯一且不超过20，gold只能来自同一候选集。

消费端将模型返回的索引映射为安全引用ID，输出case键、候选数、ranked IDs、分数、gold命中率和用量，不保存查询、候选正文、响应回显或向量；报告带稳定hash，可用于后续请求集/结果对账。当前仅有合成契约测试，未调用重排模型、未连接数据库、未写生产索引。

现有8条重排预检仍为 `rerankerProfileVerified=false`；真实重排获批后，运行时应复用该契约并逐条持久化/ACK，失败终态不可重试。重排通过也只证明候选排序消费链，仍需与本地/外部generation、锚点证据、人工60题和完整问答验收对账。
