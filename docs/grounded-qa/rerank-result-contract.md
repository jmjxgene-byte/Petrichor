# 重排结果消费契约

2026-09-10：新增离线重排结果消费模块。输入只允许 `results[{index,relevance_score}]` 和 `usage.total_tokens`，响应必须与候选数量一致，索引按0开始连续且分数非递增；越界、重复、缺索引、乱序、额外字段或正文回显均拒绝。候选ID必须唯一且不超过20，gold只能来自同一候选集。

消费端将模型返回的索引映射为安全引用ID，输出case键、候选数、ranked IDs、分数、gold命中率和用量，不保存查询、候选正文、响应回显或向量；报告带稳定hash，可用于后续请求集/结果对账。当前仅有合成契约测试，未调用重排模型、未连接数据库、未写生产索引。

2026-09-10 已完成一次经授权的 8 条合成重排调用。执行目录为受限 `.data` spool，8 个请求均收到主机与运行时 ACK，模型调用 8 次、重试 0 次、数据库写入 0 次，远端临时目录已清理；重排结果经本地收据、候选集和 embedding 评估对账，6 个可回答样例的 Recall@20 均为 1。原始主机终态因状态数组仍使用固定 22 项而报告失败，未将该失败误报为完整终态；修复后的对账器确认 8 个结果包、hash、字节数和安全字段均一致，并保留 `sourceTerminalPassed=false` 及错误类别供审计。供应商未返回 token 用量，因此本次费用未验证，不能据此开启生产外部重排或语义开关。
