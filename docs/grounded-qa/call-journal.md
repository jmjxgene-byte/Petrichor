# 逐调用持久化日志（离线执行层）

2026-09-09。采用调用前固定身份、响应后立即持久化的原则；复用已验证的私有文件分块，不新增数据库、云存储或公开URL。模块没有直接网络或模型接口，只接受调用方提供的回调；真实provider执行器尚未接入，也未部署。

## 状态和执行顺序

- 合同绑定executionId、planHash、providerProfileHash、每次调用类别和完整请求JSON的hash；不保存请求正文或凭证。最大14次文档嵌入、8次查询嵌入、8次重排。
- 批次先校验全部请求hash，才允许第一项开始。调用前排他创建call目录并fsync意图；两进程竞争时只能有一个进入回调。
- 回调只应返回已经校验、脱敏的响应字节，不能包含Key。最大256KiB，使用分块/整体SHA和原子完成收据保存；当前项完整落盘后才允许下一项。
- `not_started`：尚未创建调用目录；`outcome_unknown`：已预约但没有可验证的完成收据；`persisted`：合同、意图、manifest、文件和收据均一致。
- 再次读取persisted结果不调用回调；unknown明确失败且不重试、不跳过到后续项。损坏、权限/链接、合同或provider档案变化也不触发重新生成。
- 即使响应文件已存在，只要完成收据缺失，仍保留数据并返回unknown，不擅自补出成功状态。错误仅固定分类，不保存回调原始异常。

## 验证

`verify-canary-journal-local.ts` 以假回调产生180016字节响应，之后启动独立Bun进程；新进程的回调一旦调用就失败，但实际直接复用了原文件。simulatedInvocations=1、recoveryReused=true、完整SHA `030d3731f9d4ccf31346c778f447c66ee1c0be0f5397b8708df335935551137f` 一致，passed/cleanupOk=true，真实模型/数据库调用0。

测试覆盖单项/整批顺序、并发只调用一次、成功复用、前序失败阻止后续、未知项不重试、末项hash不符时首项也不执行、调用上限、provider变更、响应超限、响应篡改和缺失收据。首轮新代码的ordinal变量引用错误发生在回调前并被测试/类型检查发现，修正为input.ordinal后复验；没有真实调用或数据损失。

另以fsync故障注入验证：响应返回后持久化失败仍为outcome_unknown，重复执行被阻止且回调总次数为1。最终完整回归1543通过/40既有跳过，类型/Lint/build通过；真实模型、数据库和远端调用均为0。
